## 0. URL topology (important — the original prompt was wrong)

The URL `https://sls.kapo.zh.ch/login` returns **HTTP 404** ("Secure Entry
Server"). So does `https://sls.kapo.zh.ch/`. The Playwright author must NOT
navigate to `https://sls.kapo.zh.ch/login` directly.

The real entry points are:

| Purpose | URL | Notes |
|---|---|---|
| Public app entry | `https://www.hotelkontrolle.zh.ch/HoKoDMZ/login.xhtml` | JSF/JBoss-style app. Issues a 302 redirect into SAML SSO. |
| SAML/SLS auth endpoint | `https://sls.kapo.zh.ch/login/sls/auth` | The actual page that renders the username/password form. URL is reached via SAMLRequest query string after being bounced from hotelkontrolle.zh.ch. |
| SLS samlauth bounce | `https://www.hotelkontrolle.zh.ch/login/sls/samlauth?RequestedPage=...` | Intermediate hop set by the WAF (USP Secure Entry Server). Don't hard-code; follow redirects. |

**Recommended Playwright entry:** start at
`https://www.hotelkontrolle.zh.ch/HoKoDMZ/login.xhtml` and let the browser
follow the 302 chain. Page title after redirects is `Secure Login Service`.

WAF / Server: `Server: Secure Entry Server` (USP / Airlock-style reverse
proxy). Cookies set during the bounce:

- `SCDID_S` (HttpOnly, Secure) — session correlator on hotelkontrolle.zh.ch
- `SLSLanguage` (HttpOnly, Secure, max-age 94608000) — UI language pref on sls.kapo.zh.ch
- `SCDIDidpBroker_S` (HttpOnly, Secure) — IdP-broker session on sls.kapo.zh.ch

Security headers seen on the SLS page:
`Strict-Transport-Security: max-age=15768000`,
`X-Frame-Options: sameorigin`,
`X-Content-Type-Options: nosniff`,
`Referrer-Policy: origin-when-cross-origin`,
`Cache-Control: no-cache,no-store,max-age=0`.

## 1. Login page

- **Observed URL:** `https://sls.kapo.zh.ch/login/sls/auth?SAMLRequest=<base64>`
  (the SAMLRequest is generated by hotelkontrolle.zh.ch on each visit;
  treat it as opaque)
- **Page title:** `Secure Login Service`
- **Heading (German):** "Anmeldung" — "Bitte geben Sie Ihre Benutzerangaben ein."
- **Language selector:** Top-right `EN` / `DE` links (`?language=en` /
  `?language=de`). Language is persisted via the `SLSLanguage` cookie. Default
  in our probe was `de`.

### Form

The form is a plain HTML POST (no React/Vue/JSF in this view). Form element:

```html
<form action="auth" method="post" name="LoginForm" onsubmit="return checkFormSubmit();">
```

- `action="auth"` is relative → resolves to `https://sls.kapo.zh.ch/login/sls/auth`
- `onsubmit` calls `checkFormSubmit()` which prevents double-submit (sets a
  module-level `formSubmitted` boolean). This shouldn't trip Playwright's
  `page.click()` but be aware if you ever `form.submit()` programmatically.
- Body has `onload="setFocus('LoginForm', 0);"` — first field auto-focuses.

### Hidden inputs / CSRF

**No hidden CSRF token was rendered in the form HTML.** Authentication state
is carried via the `SCDIDidpBroker_S` cookie set on the GET. Make sure
Playwright is using a persistent context (or at least one that follows cookies
from the GET to the POST).

### Post-login URL pattern

**Unknown** (we did not submit). After successful SAML, the SLS service
typically auto-POSTs a `SAMLResponse` form back to the SP
(`https://www.hotelkontrolle.zh.ch/...`), so expect a page transition with a
brief invisible auto-submit form. Playwright should `waitForURL(/hotelkontrolle\.zh\.ch/)`
after clicking Weiter.

### Captcha / 2FA

- **Captcha:** None visible. No reCAPTCHA, hCaptcha, or image-puzzle in the
  initial HTML or the rendered snapshot. There's a load of
  `/sil-bid-check/ses.js` (USP's session-integrity script) — this is a
  client fingerprinting/integrity script, **not** a captcha, but it may
  reject headless browsers if the fingerprint is suspicious. Run Playwright
  with a real Chromium build (not `webkit`/`firefox` if possible) and
  consider `headless: false` for the first dry runs.
- **2FA:** No second factor visible on this page. The SLS service is
  multi-step; if 2FA is required for this account, a second page will appear
  after pressing Weiter. We could not verify because we stopped at the wall.

### `ses.js` (USP browser fingerprint)

`<script src="/sil-bid-check/ses.js">` plus
`<span class="userData" id="sesUserData" name="sesUserData">` plus
`sesStart("LoginForm");` — this writes a fingerprint into a hidden field of
the form before submit. With a normal Playwright Chromium it should "just
work", but if logins start failing silently, this is the prime suspect.

## 2. Navigation to entry form

**Not yet probed** — login wall.

Expected (from public docs): after successful SSO you land somewhere under
`https://www.hotelkontrolle.zh.ch/HoKoDMZ/` and the navigation should expose
a "Meldeschein erfassen" / "Neuer Meldeschein" link. The `.xhtml` extension
indicates **JavaServer Faces (JSF / Mojarra)**, which is important:

- JSF element IDs are auto-prefixed like `formName:fieldName` (colons).
- JSF form posts include a `javax.faces.ViewState` hidden input that **must**
  round-trip on every action. Playwright clicks on JSF buttons work fine, but
  raw `fetch()` calls don't.
- Many JSF apps use `<h:commandLink>` rendered as `<a onclick="...jsf.ajax...">`
  rather than real `<button>` elements. Prefer `getByRole('link', {name: ...})`
  or `getByText(...)` over CSS selectors.
- Partial AJAX updates are common — wait with `page.waitForResponse(/jsf.ajax/)`
  or `page.waitForLoadState('networkidle')` after each action.

URL of the form: **unknown**, fill in after first login.

## 4. Multi-row entry

**Not yet probed.** Two likely shapes:

- **Shape A:** one row per page → submit → land back on list → "Neu" again.
  Slower but bulletproof for Playwright (no race conditions).

The Playwright script should detect this dynamically after the first login.

## 7. Pitfalls / quirks

1. **Wrong base URL in the spec.** `https://sls.kapo.zh.ch/login` → 404. Use
   `https://www.hotelkontrolle.zh.ch/HoKoDMZ/login.xhtml` and let it redirect.
2. **USP browser-integrity script (`ses.js`).** May reject headless browsers.
   Start with `headless: false` for development; switch to headless after
   verifying.
3. **JSF ViewState.** The post-login app is JSF (`.xhtml`). Never bypass the
   form by hand-crafting POSTs — let Playwright submit the rendered form so
   `javax.faces.ViewState` round-trips.
4. **AJAX races.** Use `page.waitForLoadState('networkidle')` or
   `waitForResponse(/HoKoDMZ/)` after each click. JSF partial updates
   re-render DOM subtrees, so element refs become stale immediately.
5. **`<input>` elements have no `id` on the login page.** Use
   `name="userid"` / `name="password"` as primary selectors — labels point at
   `for="userid"` for both inputs (yes, the password label too — it's an HTML
   bug in their template). `getByLabel('Passwort')` may match both fields in
   strict mode; prefer `input[name="password"]`.
6. **Cookies are HttpOnly + Secure.** Always run over HTTPS (default). Never
   try to read these cookies from the page via JS — they're invisible to it.
7. **Login auto-submit.** `setFocus('LoginForm', 0)` auto-focuses the
   username on body load. Don't `click()` the username field unnecessarily —
   just `fill()`.
8. **`autocomplete="off"`** on both inputs — Playwright `fill()` handles
   this correctly, but `page.type()` with browser-saved credentials enabled
   will not auto-populate.
9. **Caching disabled aggressively.** `Cache-Control: no-cache,no-store`.
   Every page load is a full round-trip.
10. **Bilingual content (DE/EN).** The `SLSLanguage` cookie persists. If the
    user has the app set to English, button labels will be different
    ("Login" vs "Anmelden"). The Playwright script should set
    `?language=de` once or rely on `getByRole('button')` matching either
    text via regex.
11. **`X-Frame-Options: sameorigin`.** Cannot embed in iframes from other
    hosts — irrelevant for Playwright but blocks any debug-overlay approach.
12. **No CSRF token on login form.** Authentication is anchored only on the
    `SCDIDidpBroker_S` cookie set when GETting the login page. Don't reuse
    cookies across runs unless you also reuse the SAMLRequest binding —
    safest is a fresh navigate per session.
